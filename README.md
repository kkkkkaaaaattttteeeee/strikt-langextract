# Извлечение S-P-O триплетов из русских новостей

Оценка пригодности LangExtract и локальных LLM для извлечения структурированных
фактов «субъект — предикат — объект» из русскоязычных новостных текстов.

---

## Задача

Проверить, можно ли доверять автоматическому извлечению S-P-O триплетов
из новостей и использовать результат в смежных задачах команды
(дедупликация, NER, оценка покрытия, аналитика вакансий).

**Вход:** 49 текстов из Ведомостей.
**Gold:** 10 текстов, 191 эталонный триплет.
**Выход:** оценка качества моделей + рекомендации по применению.

---

## Данные

| Файл | Описание |
|---|---|
| `data/articles.csv` | 49 новостных текстов |
| `data/gold.csv` | Эталон: 191 триплет на 10 текстах |

Gold размечен вручную через ChatGPT с последующей чисткой:
- удалены местоимения в субъектах,
- удалены причастия и модальные слова в предикатах,
- объекты обрезаны до именной группы,
- удалены вводные конструкции и плейсхолдеры.

---

## Метод

**Эксперимент 1 — LangExtract + Qwen2.5:7b / 3b**
- Промпт v3 + few-shot примеры
- LangExtract сам строит запрос к Ollama и парсит ответ
- Source grounding: триплет привязан к позиции в тексте

**Эксперимент 2 — Qwen3.8:27b через прямой Ollama API**
- Промпт v6 + JSON Lines
- Обход LangExtract: библиотека не совместима с thinking-режимом

**Пайплайн обработки:**
1. Предобработка текста — HTML, ссылки, HTML-сущности, пробелы.
2. Прогон модели.
3. Постобработка триплетов:
   - удаление местоимений в S, причастий и модальных в P,
   - обрезка объектов, обрывающихся на предлог,
   - схлопывание перечислений (5+ одинаковых P+O),
   - удаление near-дублей.
4. Метрики: Jaccard soft, BERTScore, F1 по компонентам S / P / O.

---

## Результаты

| Модель | Способ вызова | Jaccard F1 | BERTScore | Recall |
|---|---|---|---|---|
| Qwen2.5:7b | LangExtract | **0.459** | — | 0.466 |
| Qwen3.8:27b | Прямой API | 0.445 | **0.621** | **0.601** |

**F1 по компонентам (Qwen3.8:27b):**

| Компонент | F1 |
|---|---|
| Предикаты | **0.526** |
| Субъекты | 0.475 |
| Объекты | 0.403 |

**Влияние постобработки:**

| Этап | Precision | Recall | F1 |
|---|---|---|---|
| Raw | 0.358 | 0.604 | 0.422 |
| Cleaned | 0.386 | 0.601 | **0.445** |

Постобработка дала **+0.022 к F1** — Precision вырос, Recall почти не пострадал.

---

## Выводы

1. **LangExtract совместим только с моделями без thinking-режима.**
   Qwen3.5, Qwen3.8, Gemma 3 падают с `empty tokens` — библиотека не
   пробрасывает `think=False` в Ollama.

2. **Для thinking-моделей нужен прямой API с `think=False`.**
   Даёт сопоставимое качество, но теряет source grounding.

3. **BERTScore на 40% выше Jaccard.**
   Модель даёт семантически корректные триплеты в своих формулировках.
   Jaccard занижает реальное качество из-за перефразирований.

4. **Слабое место — объекты (F1 = 0.403).**
   Модель добавляет детали, которые Jaccard не прощает.
   Сильная сторона — предикаты (F1 = 0.526).


**Практический итог:** задача решаема на уровне **полуавтоматической
разметки**. Модель находит 60% фактов, эксперт отсеивает мусор.
Экономия времени ~2x.
