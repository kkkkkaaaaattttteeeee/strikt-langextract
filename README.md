# Оценка LangExtract для извлечения S-P-O триплетов из русских новостей

Оценка библиотеки **LangExtract** и локальных LLM (**qwen2.5:3b/7b**, **qwen3.5:9b**,
**Qwen3.8:27B**) на задаче извлечения структурированных фактов
«субъект — предикат — объект» из русскоязычных новостных текстов.

---

## 🎯 Задача

Двухуровневая оценка:

1. **Прикладной уровень** — насколько хорошо связка «LangExtract + локальная LLM»
   извлекает S-P-O триплеты из реальных новостей
2. **Инструментальный уровень** — что даёт сама библиотека: фичи, ограничения,
   баги, пригодность для прототипа и прода

**Данные:** 49 статей Ведомостей · gold standard: 191 триплет на 10 текстах

---

## 📚 Три итерации — три ноутбука

### Ноутбук 1 — «Работает ли пайплайн вообще?»

- **Промпт:** простой, без грамматических правил
- **Модели:** qwen2.5:3b, qwen2.5:7b
- **Текстов:** 49
- **Фреймворк:** LangExtract
- **Результат:** 7b → 0.459, 3b → 0.289 (Jaccard soft F1)
- **Проблема:** топ-сущности замусорены местоимениями и модальными словами
- **Вывод:** пайплайн работает, но промпт не соблюдается

### Ноутбук 2 — «Максимум качества»

- **Промпт:** `prompt_v6` — жёсткие правила + 6 few-shot примеров
- **Модель:** Qwen3.8:27B (Q3_K_M)
- **Текстов:** 10
- **Фреймворк:** прямой Ollama API (`num_ctx=8192`, `think=False`, `seed=42`)
- **Результат:** Jaccard F1 = **0.445**, BERTScore F1 = **0.621**
- **Вывод:** промпт важнее модели — жёсткие правила дали +0.29 F1

### Ноутбук 3 — «Оценка LangExtract»

- **Промпт:** тот же `prompt_v6`
- **Модель:** qwen3.5:9b
- **Текстов:** 10
- **Фреймворк:** `lx.extract()`
- **Результат:** Jaccard F1 = 0.297, BERTScore F1 = 0.591
- **Найдено:** 5 багов и ограничений библиотеки

## 🎓 F1 по компонентам триплета

| Компонент | Qwen3.8:27B | qwen3.5:9b | Δ |
|---|---|---|---|
| **Субъект** | 0.475 | 0.352 | −26% |
| **Предикат** | 0.526 | 0.420 | −20% |
| **Объект** | **0.403** | **0.195** | **−52%** |

```
Субъект    ███████████████████████  0.475 (27B)
           ██████████████████       0.352 (9b)

Предикат   ██████████████████████████  0.526 (27B)
           █████████████████████        0.420 (9b)

Объект     ████████████████████  0.403 (27B)
           ██████████            0.195 (9b)  ← главный провал
```

**Почему 9b проваливается по объектам:** модель не соблюдает правило промпта
«объект — именная группа ≤7 слов, без придаточных с что/как/когда». Пример:

- **Gold:** `забота → это → стремление`
- **9b выдал:** `забота → это → что забота – это стремление сделать жизнь партнёра проще`

Модель копирует придаточное целиком — не хватает «мощности» одновременно
понять текст и обрезать объект до ядра.

## 🏆 Ключевые выводы

### 1. Промпт важнее модели

Жёсткий `prompt_v6` + 6 few-shot примеров даёт рост качества,
**сопоставимый с увеличением модели в 4 раза** (7b → 27B).

**Практический смысл:** если ограничен бюджет на GPU — сначала оптимизируйте
промпт, а не гонитесь за большей моделью.

### 2. Размер модели определяет структуру, а не семантику

Обе модели (9b и 27B) дают близкий **BERTScore** — семантически извлекают
корректно. Но **Jaccard различается в 1.5 раза** — 9b не соблюдает
грамматические правила промпта.

| | 9b | 27B |
|---|---|---|
| Понимание текста | ✅ | ✅ |
| Соблюдение правил | ❌ 20–30% нарушений | ✅ <10% |
| Обрезка объектов до ядра | ❌ | ✅ |
| BERTScore | 0.587 | 0.621 |
| Jaccard | 0.297 | 0.445 |

**Практический смысл:** для задач «найти факты» хватит 9b.
Для задач «воспроизвести структуру» — нужна 27B.

### 3. Провал по объектам — главная проблема 9b

F1 объекта у 9b = **0.195** против **0.403** у 27B. Модель не обрезает
придаточные, копирует клаузы целиком.

**Практический смысл:** постобработка объектов (обрезка до 5 слов)
даёт **+0.013 F1** — но потолок механической очистки ограничен.

## 🔬 LangExtract — оценка библиотеки

### ✅ Что работает (5 из 10 проверенных фич)

| Фича | Детали |
|---|---|
| **Alignment через `CharInterval`** | **89% EXACT** — привязка к позиции в тексте |
| HTML-визуализация | 733 docs/s |
| JSONL-экспорт | 423 docs/s |
| Структурные атрибуты | `subject/predicate/object` парсятся |
| Few-shot examples | 6 примеров принимаются |

### ⚠️ Ограничения

| Фича | Статус | Детали |
|---|---|---|
| Chunking длинных текстов | ⚠️ ограничение | покрытие **8.9%** на тексте 17k |
| Timeout 60с | ⚠️ патч нужен | monkey-patch `_ollama_query` |

## 📋 Итоговая оценка LangExtract

| Критерий | Оценка | Обоснование |
|---|---|---|
| Функциональность | 7/10 | базовые фичи работают, chunking+multi-pass — нет |
| Надёжность | 4/10 | silent data loss критичен для прода |
| Гибкость настройки | 3/10 | timeout и resolver — только через monkey-patch |
| **Для прототипа** | **8/10** | быстрый старт, alignment из коробки |
| **Для прода** | **3/10** | нужны патчи, валидация, постобработка |

---

## ⚠️ Ограничения проекта

1. **Gold standard — 10 текстов, 191 триплет** — небольшая выборка
2. **Патчи LangExtract** (`Resolver.resolve`, `_ollama_query`) — хрупкие,
   теряются при рестарте runtime
3. **`pymorphy3` ломает имена собственные** — `Тайлер` → `тайлера`
4. **Прямое сравнение 7b и 27B некорректно** — они на разных промптах

---

## 📌 Итог одной фразой

> Локальные LLM дают **семантически корректные** триплеты (BERTScore 0.59–0.62),
> но **LangExtract не готова к проду** без патчей: silent data loss при chunking
> теряет до 91% длинных текстов без предупреждения. Для прототипа — отличный
> инструмент (8/10), для прода — патчи + валидация покрытия или переход
> на прямой Ollama API.
